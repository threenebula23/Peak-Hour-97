## D01 — карточка запроса
**Решение:** в карточке запроса показывать имя требуемого файла
(до 12 символов) и его папку, а не только иконку типа. `required` —
конкретные id файлов, не фильтры по типу.
**GDD:** §7 (нужные файлы — по имени+папке, привязка по id).
**Статус v2.0: устарело.** В v2 `required` — это 1–3 слота контейнера, файлы
выбирает игрок; конкретные id не зашиты (D32, GDD §7).

## D02 — расход/удаление файлов и склад
**Решение:** файлы **не расходуются** при отправке, но после успешной
отправки получают cooldown 20 с (нельзя снова прикрепить). Обычные
файлы можно удалять ТОЛЬКО в подготовке (долгое удержание/ПКМ);
зловредные — в любой фазе. «Конец забега по складу» считается
поражением, но пройденные 30+ часов засчитываются; в итоговом
отчёте это указывается явно.
**GDD:** §3, §5, §16.
**Статус v2.0: устарело.** Файлы **расходуются** при успешной отправке
(cooldown 0); при отмене/таймауте сохраняются (D33). «Конец забега по
складу» не используется: поражение только по SLA (D40, GDD §16). Удаление
неприкреплённого файла в подготовке — без штрафа (D44).

## D03 — заморозка таймеров модалками
**Решение:** пока открыта модалка мини-игры или панель соединения —
спавн приёма и таймеры пакетов в буфере **останавливаются**; таймер
активного запроса продолжает идти; при полном буфере новые пакеты
не спавнятся.
**GDD:** §6, §8, §8.4.
**Статус v2.0: частично устарело.** Мини-игра отправки не ставит час на
паузу: она морозит спавн/загрузку, спавн запросов и таймер своего запроса;
другие таймеры идут. Мини-игра атаки ставит на паузу весь час (D34/D38).

## D04 — полоска соединения
**Решение:** `W = clamp(0.30 − 0.005×(hour−1) − 0.005×successes
+ 0.05×zone_upgrade_level, 0.18, 0.36)`. Скорости палочек
440/340/280 px/с; окна попадания ~130–200 мс; апгрейд зоны применяется
внутри формулы, cap 0.36.
**GDD:** §11.
**Статус v2.0: устарело.** Полоска соединения удалена. TCP/UDP — переключатель
оплаты/скорости: TCP ×1.15 к выплате, UDP ×0.8 ко времени (D33, GDD §11).
**Статус v3.0: формула снова актуальна.** TCP-соединение вернулось (D45):
та же формула зоны, скорости 440/340/280, 3 попадания; промах −4 SLA / 8 с,
Esc — 0 SLA / 4 с. UDP соединения не требует.

## D05 — один источник истины
**Решение:** буфер = `4 + 2×buffer_upgrades` (max 8); зона — только
формула D04; `max_requests` — только из таблицы сложности
(`balance.json → difficulty`); в окне «Отправка» максимум 4 видимых
карточки; при 5-м запросе — скролл и высота карточек 56 px.
**GDD:** §6, §7, §11.
**Статус v2.0: устарело в числах.** Буфер = 6 + уровень `lot_channel`, max 12;
`request_cap` берётся из `hours[]` (2/5/5/6/6/7/7/7/8), а не из legacy
`difficulty`. Правило «4 карточки, дальше скролл, высота 56 px» остаётся
(D29, GDD §6–7).

## D06 — файл в нескольких запросах
**Решение:** файл может входить в `required` нескольких запросов, но
`attached` — только в одном; второй запрос показывает файл серым.
При `failed` файла все запросы, где он `required`, отменяются со штрафом.
**GDD:** §7.
**Статус v2.0: частично устарело.** Файл по-прежнему прикрепляется только к
одному запросу; но `required` больше не содержит конкретных id, поэтому
правило «все запросы, где он `required`» не применяется. При `locked`/
`failed`/`malicious` файл просто открепляется (D32).

## D07 — атаки вне буфера и единая таблица штрафов
**Решение:** атаки не занимают буфер и не вытесняются ими; отдельный
слой карточек атак. Единая таблица урона: мусор −5 SLA, DDoS −15,
фишинг −10, шифровальщик −10 (вместо глобального −15).
**GDD:** §12.
**Статус v2.0: устарело.** Карточек/оверлеев атак больше нет: каждая атака —
мини-игра, которая ставит час на паузу. Урон/награда — по
`attacks.kinds.*.tiers`, плюс эффекты DDoS/фишинга/шифровальщика
(D38/D39, GDD §12.1).

## D08 — видимые теллы
**Решение:** у пакета показывать расширение файла; у шифровальщика —
красный квадрат 4×4; у фишинга — client_id формата `id_XXXX` с неверным
символом (например `id_7F3К`, кириллическая К) и серый аватар.
`locked`/malicious файл остаётся кликабельным для уничтожения.
**GDD:** §20.
**Статус v2.0: устарело.** Зловредных пакетов/фишинговых запросов и их
теллов нет; атаки вынесены в отдельные мини-игры (D38, GDD §12.1, §20).

## D09 — состояния-флаги
**Решение:** состояния — флаги, а не один enum:
`FileItem.location` (registry/folder/attached/locked/malicious/failed),
`attached_request`, `malicious_kind`, `lock_until`;
у запроса `slot_reserved`, `connected`, `minigame_active`.
Таблица переходов при истечении таймера (загрузка/соединение/мини-игра)
— в `docs/IMPLEMENTATION.md`.
**GDD:** §17.
**Статус v2.0: обновлено.** Добавлены `table` и `sending`; `connected` —
legacy и всегда `true` (полоски нет). Резервации приёма живут в папке, а не
в запросе (D31/D32, GDD §17).
**Статус v3.0: обновлено.** `connected` снова рабочий флаг TCP; добавлены
`connecting`, `connect_attempts`, `connect_cooldown_until`, `required_by`
(D45/D46, GDD §17).

## D10 — поведение Esc
**Решение:** в час — пауза; в мини-игре — no-op; в панели соединения —
отмена (слот освобождается, запрос остаётся); закрытие модалок — только
кнопкой или таймаутом.
**GDD:** §18.
**Статус v2.0: частично устарело.** Панели соединения нет. В мини-игре
отправки `Esc` во время игры — no-op; в мини-игре атаки — двухшаговое
подтверждение `СДАТЬСЯ`; на экране результата — `ПРОДОЛЖИТЬ` (D34, GDD §18).
**Статус v3.0: обновлено.** TCP-панель вернулась: `Esc` отменяет соединение
без штрафа SLA, с кулдауном 4 с (D45, GDD §11.1, §18).

## D11 — устойчивость к лагам
**Решение:** `delta = min(delta, 0.1)`; авто-пауза при
`NOTIFICATION_APPLICATION_FOCUS_OUT`; `Engine.max_fps = 60`.
**GDD:** §8.

## D12 — баланс
**Решение:** доход/час пересчитан: ожидаемо ~500/800/1200/1800/2200
для часов 1/2/3/5/9. Цены магазина подняты так, что полный выкуп
реалистичен к часу 8–9. SLA-прирост: приём +0.5, отправка +1,
отражённая атака +1. Штрафы масштабируются: −(10 + 2×hour) за таймаут
и подобных. Таблица сложности останавливается на часе 8; дальше те же
значения, но +5 % к скорости спавна каждые 2 часа.
**GDD:** §12, §13, §23.
**v1.2:** старт SLA — 128/200; штраф за потерю пакета — по типу (D19).
**Статус v2.0: устарело.** Доход — цели 65/220/380/560/760/980/1200/1450/
1700; старт SLA 60/60; пассивных +0.5/+1 нет, есть +15 в начале часа и
награды атак. «Полный выкуп к H8–H9» не подтверждён (56,7–57,9 % дерева в v3).
Штраф `−(10+2×hour)` сохранён (D29/D40/D50, GDD §12–13).

## D13 — магазин
**Решение:** 9 позиций: 3-й слот 250, 4-й слот 450, буфер +2 — 200×2,
таймер пакетов +4 с — 350×3, зона +5 % — 300×3, канал +25 — 250×4,
секция — 300×5, поиск — 250, щит — 400. Сканер и автосортировка —
резерв (вырезаны из прототипа).
**GDD:** §14.
**v1.2:** добавлена 10-я позиция «SLA +24» (300, max 3); открытия — D23.
**Статус v2.0: устарело.** 8 лотов, 3 оффера, рероллы и замки; зоны/секции/
поиска в магазине нет. В v3.1 — **9 лотов** и дерево **8 825 $** (D50, D55);
прежние числа v1/v2 — история.

## D14 — фон
**Решение:** шейдер фона — статичный градиент + слабый шум 320×180,
без полноэкранного fbm; CRT-эффект убрать.
**GDD:** §21.
**v1.2:** фон — тёплый бумажный дизеринг/панели, см. D18.
**v1.2.1:** VHS возвращён только в главное меню, игровой UI без CRT (D27).

## D15 — шрифт
**Решение:** основной шрифт — **Handjet** (OFL 1.1, полная кириллица,
вариативный: wght 100–900, ELGR 1–2, ELSH 0–16; средняя ширина ≈0.36 em,
файл `Handjet[ELGR,ELSH,wght].ttf` из google/fonts/ofl/handjet + OFL.txt).
Press Start 2P остаётся только для крупных заголовков/логотипа
(слишком широкий: 17 символов не влезают в карточку 132 px).
**Pixelify Sans удалить из темы** (неполная кириллица: нет глифов О и П).
Допустимые кегли: **10 / 12 / 16 / 24** (Handjet узкий, поэтому 10
разрешён).
**GDD:** §21.
**Статус v3.0: заменено D51.** Основной шрифт — **Golos Text**, шкала
**11/13/17/26**; Press Start 2P — только логотип и цифры; Handjet — legacy.
**Статус v3.1:** заменено D56 — тело на Kechusilka, крупный текст на
DisplayOTF, Golos Text остаётся fallback.

## D16 — порядок P0
**Решение:** порядок P0: данные/реестр → слоты → приём/отправка → UI.
**GDD:** §23.
**v1.2:** календарь открытий — D23; в часе 1 атак нет.
**Статус v2.0: исторический.** Актуальная структура — `main.gd` +

## D17 — quality/retry
**Решение:** заглушка качества возвращает 1.0; кнопка «Переделать»
оставлена, но не влияет на quality (только перезапуск заглушки);
«самый сложный тип» заменён средним коэффициентом — правило выбора
мини-игры в GDD §8.4/§10:
`coeff = {text:1.0, sound:2.0, photo:3.0, video:4.0}`,
`difficulty = sum(coeff)/n`, пороги `<1.5 text, <2.5 sound,
<3.5 photo, иначе video`; `MiniGame.start(type, difficulty)`.
**GDD:** §4, §8.4, §10.
**Статус v2.0: устарело.** Заглушки качества и кнопки «Переделать» нет:
`q` даёт мини-игра. Выбор игры — по плотному списку достижимых сумм и
коэффициентам 1/2/4/8 (D34/D35, GDD §8.4, §10).


## D18 — UI v2 «Kaleidos»

**Решение:** интерфейс переведён на тёплую бумагу, тонкие 1 px контуры,
мягкие тени `#00000018`, скругления 3–4 px и бирюзовый акцент `#2F7F8F`.
Окно — **1920×1080**, логический viewport — **1280×720**,

Меньше декоративных подписей, меню и «коробок»; иллюстрации и иконки
по-прежнему рисуются кодом.
**GDD:** §1–2, §21.

## D19 — SLA и магазин v1.2

**Решение:** старт забега — **SLA 128 / 200**. Потеря пакета списывает SLA
по типу: `text 2`, `sound 4`, `photo 8`, `video 16`. В магазин добавлена
10-я позиция **«SLA +24»** — 300, max 3 уровня. Остальные 9 позиций D13
сохраняются; итого 10.
**GDD:** §4, §12, §14.
**Статус v2.0: устарело.** Старт SLA 60/60; лота «SLA +24» нет, кап в v3
растёт на +40 за уровень `lot_sla` до 220. Потеря пакета по типу сохранена
(D29/D40/D50, GDD §12).

## D20 — таймеры и grace

**Решение:** таймеры пакета/запроса считаются как
`(base − 0.5×(h−1)) × grace(h) + 4×timer_level`, где grace:
`h1 1.5`, `h2 1.35`, `h3 1.2`, `h4+ 1.0`. Итоги: h1 30/45,
h2 26.325/39.825, h3 22.8/34.8, h4 18.5/28.5, h5 18/28, далее
плавно до h9 16/26. Апгрейд «Таймер пакетов +4 с» даёт чистые +4 с
поверх grace.
**GDD:** §8.
**Статус v2.0: устарело.** Grace и per-hour scaling отменены: пакет 20 с,
запрос 30 + 5×уровень (max 55) (D29, GDD §8).

## D21 — канал v1.2

**Решение:** в нагрузку канала входят только активные передачи
(`loading`/`sending`): `load = Σ weight(active_transfers)`. Фон и занятые
слоты не грузят; idle = 0 %. `capacity = 80 + 25×channel_level`,
`factor = max(1.0, load / capacity)`, `actual_time = base_time × factor`.
**GDD:** §9.
**Статус v2.0: устарело в числах.** `capacity = 10 + 6×level` (10…46);
формула нагрузки и idle=0 сохранены (D29, GDD §9).

## D22 — TCP-соединение

**Решение:** промах в полоске закрывает панель, автоповтора нет — игрок
снова нажимает «Соединиться». `Request.connected` выставляется только
после успешного прохождения; при промахе слот освобождается, запрос
остаётся. `Esc` — отмена с тем же результатом.
**GDD:** §11, §17.
**Статус v2.0: устарело.** Полоски/панели соединения нет; `connected` всегда
`true`. TCP/UDP — переключатель выплаты/времени (D33, GDD §11).

## D23 — открытия и мета

**Решение:** магазин открывается с часа 2 и скрыт во время часа
(в подготовке после часа 1). Мета-награды выдаются **постепенно**:
`survive_hour_3` — после 3-го часа, `survive_hour_5` — после 5-го,
`complete_run` — после 9-го. `Game.run_meta_awards` копит открытия забега;
`RunResultModal` показывает «ОТКРЫТО: …», мета сохраняется между забегами
(`Game.meta_unlocks`, save). Типы: text h1, sound h2, photo/video h3+.
**Час 1 — без атак**; junk/ddos — h2, phishing — h3, ransomware — h4
(`difficulty.attacks = 0,1,1,2,2,3,3,4,4`). `minigame_advanced` — резерв
под будущие мини-игры, контента пока нет.
**GDD:** §3, §10, §15, §23.
**Статус v2.0: обновлено.** Магазин с H2 и мета 3/5/9 сохранены. Типы H1
text/sound, photo с H2, video с H3. Атаки: junk/ddos с H2, phishing с H4,
ransomware с H5 (по `weight_by_hour`); `minigame_advanced` по-прежнему
резерв (D29/D38, GDD §3, §14). Мета-ключ `search` остаётся в данных, но
UI-поиск в v2 не подключён — как готовая фича не документируется.

## D24 — UX и читаемость

**Решение:** имена папок берутся из пула `names_ru.json` и уникализируются
внутри секции (`Имя`, `Имя 2`), пустые папки удаляются. Текущая папка и
дерево автообновляются после приёма/перемещения. У прикреплённых файлов —
зелёная галочка. «Уничтожить содержимое» папки реально удаляет файлы после
подтверждения и снимает 5 SLA, пустая папка — без штрафа. Магазин доступен
в подготовке после часа 1, без крестика («Закрыть»/`Esc`). После открытия
«Поиска» появляется поле поиска по имени и фильтр текущей папки. Настройки
открываются с главного экрана. «Спокойный фон» — плоская `PAPER` без dither.
Маскот **БАЙТ** ведёт короткий туториал первого часа. Esc на итогах забега
ведёт в главное меню (не soft-lock).
**GDD:** §18, §19, §21.
**Статус v2.0: частично.** Поле поиска не подключено (см. D23), остальное —
имена, уничтожение папки, магазин без крестика, calm-фон — в силе.

## D25 — проверки и MR-ревью

**Решение:** единый прогон — `scripts/run_all_tests.sh` (21 набор +
parse-check, **22/22 PASS**; ambient 74/0). MR дополнительно проходит

## D29 — стартовые статы и формулы

**Решение:** забег начинается с **50 $** и **SLA 60/60**. Кап SLA —
`60 + 40×sla_level`, жёсткий максимум **220**. Слоты — `1 + slot_level`
(1…5), канал — `10 + 6×channel_level` (10…46, он же даёт буфер
`6 + уровень`, 6…12), таймер запроса — `30 + 7×timer_level` (30…65),
таймер пакета — фиксированные **20 с**. Сетка папки —
`[5×4, 6×4, 7×5, 8×5, 8×6, 9×6]`. На старте 2 папки, максимум 6, новая —
**180 $**. В начале часа SLA +15 и заряды щита восстанавливаются.
**GDD:** §4, §6, §8, §9, §12, §14.
**Заменяет:** числа D05, D12, D19, D20, D21.

## D30 — сетки папок и файлы-полимино

**Решение:** каждая папка — клеточная сетка; файл — полимино: текст 1,
звук 2, фото 3, видео 4 клетки. Формы — `grid.shapes` в `data/balance.json`.
Поворот — `R` или ПКМ во время drag (0–3). Точное размещение проверяет
пересечения и границы; auto-fit идёт first-fit по строкам/столбцам. Подпись
рисуется в **верхней левой занятой** клетке, а не в пустом углу bbox
(S/Z-формы). Перемещать `attached`/`locked`/`failed`/`malicious` нельзя.
**GDD:** §5, §20.
**Заменяет:** плоские «слоты файлов» v1.

## D31 — приём, резервации и стол сортировки

**Решение:** приём резервирует клетки фигуры в папке на время загрузки;
отмена/таймаут освобождает резервацию. Полный буфер замораживает спавн, но
не сжигает бюджет часа. Стол сортировки — отдельная сетка **4×6**, доступен
в подготовке. Файл на столе нельзя прикрепить к запросу. На старте часа
стол автоматически возвращает файлы в папки; если хотя бы один не влез —
час не начинается, игрок освобождает место. Позиции на столе входят в сейв.
**GDD:** §3, §5–7, §15.
**Обновляет:** D03, D05.

## D32 — запросы и прикрепление

**Решение:** запрос требует до трёх файлов (слоты контейнера), конкретные id не
зашиты — игрок сам выбирает файлы. Файл прикреплён только к одному запросу;
со стола не прикрепляется. При `locked`/`failed`/`malicious` файл
открепляется, контейнер нужно собрать снова. Таймер запроса замирает в его
мини-игре, в очереди out-слота и во время передачи; остальные таймеры идут.
`ОТКЛОНИТЬ` — −5 $/−5 SLA.
**GDD:** §7, §8, §17.
**Заменяет:** D01, D06; обновляет D09.
**Статус v3.0: заменено D46.** Запрос снова требует конкретные `file_id`,
но их **1–4**; имена видны на карточке, есть «ПОТЕРЯН» и жёсткая резервация.

## D33 — отправка, расход файлов и TCP/UDP

**Решение:** отправка — только по явной кнопке `ОТПРАВИТЬ`; прикрепление и
закрытие мини-игры автостарт не запускают. TCP/UDP переключаются до старта:
TCP — выплата ×1.15, время ×1.0; UDP — время ×0.8, выплата **×0.85**. После
мини-игры запрос занимает out-слот или встаёт в очередь «ОЖИДАНИЕ СЛОТА»
(таймер заморожен), пока слот не освободится. При успешной отправке файлы
**расходуются**; при отмене/таймауте/конце часа сохраняются. Полоска
соединения в v2 была удалена; в v3 TCP-соединение вернулось (D45), а
`connected` снова рабочий флаг.
**GDD:** §7, §11, §17.
**Заменяет:** D02 (расход), D04, D22.
**Статус v3.0: заменено D45.** TCP снова требует полоску соединения; UDP
шлёт сразу. Выплата UDP — **×0.85** (не ×1.0), TCP — ×1.15, время UDP ×0.8.

## D34 — мини-игры: состав и контракт

**Решение:** 11 игр — семь отправки (включая удалённую в v3 игру с проводами)
и 4 атаки (`junk`, `ddos`, `phishing`, `ransomware`). Общий
контракт: без таймеров, конечная цель, локальный seeded RNG, `q ∈ 0…1`,
экран результата `q%`/вердикт и `ПРОДОЛЖИТЬ`; `finished` эмитится только
после `ПРОДОЛЖИТЬ` в модальном режиме (награда не применяется раньше).
`СДАТЬСЯ` (атаки) / `ПРОПУСТИТЬ` (отправки) с подтверждением даёт `q=0`.
Формулы `q` — GDD §10.
`Esc` во время игры отправки — no-op, в игре атаки — двухшаговое `СДАТЬСЯ`;
на результате — продолжить.
**GDD:** §10, §18.
**Заменяет:** D17 (заглушка q), D08 (теллы).
**Примечание:** строка `minigame.surrender` (`СДАТЬСЯ`) используется
мини-играми атак; у мини-игр отправки кнопка — `ПРОПУСТИТЬ`.
**Статус v3.0: заменено D47/D48.** Сейчас **10** игр: 6 отправки + 4 атаки;
игры с соединением проводов нет; у отправки 3 ступени. Общий контракт

«название + цель», полосой прогресса и двухкликовым отказом (GDD §10).

## D35 — выбор мини-игры отправки (B4)

**Решение:** коэффициенты `text 1 / sound 2 / photo 4 / video 8`;

floor(rank×4/19), 1, 4)`, `id = order[rank % 7]`, где order — семь игр v2
(включая удалённую в v3 игру с проводами). Суммы 15/19/21/22/23 недостижимы,
поэтому 28-элементный массив не перечисляется. Все 7 игр и 4 ступени были
достижимы; `S=24 → video/T4` (старый пример S−1 отменён).
**GDD:** §8.4, §10.
**Заменяет:** D17 (средний коэффициент/пороги).
**Статус v3.0: история.** Актуальная формула — **27 достижимых сумм для 1–4
файлов**, 3 ступени и фиксированная таблица `rank_games` (D49, GDD §8.4).
Старые «19 сумм / 4 ступени / rank % 7» больше не действуют.

# Решения v3.0 (D45–D52) и уточнения (D53–D56)

## D45 — TCP-соединение возвращено

**Решение:** TCP перед мини-игрой отправки снова требует мини-игру соединения
`scripts/minigames/connection_game.gd`: три палочки по очереди, скорости
**440/340/280 px/с**, три попадания в зелёную зону. UDP соединения не требует
и открывает мини-игру отправки сразу.

```
W = clamp(0.30 − 0.005×(hour−1) − 0.005×successes + 0.05×timer_level,
          0.18, 0.36)
```

- Промах/уход за край: **−4 SLA**, кулдаун повтора **8 с**, панель
  закрывается (автоповтора нет).
- `Esc`: **0 SLA**, кулдаун **4 с**, запрос остаётся.
- Таймер запроса на время соединения заморожен; час идёт.
- Успех сразу открывает мини-игру отправки, увеличивает `connect_successes`
  и **блокирует протокол** до конца запроса.
- Счётчик успехов сбрасывается на новом забеге (`reset_carry()`).
- Экономика: TCP — выплата **×1.15**, время ×1.0; UDP — выплата **×0.85**,
  время **×0.8**.
**GDD:** §11, §11.1, §11.2, §17, §18.
**Заменяет:** D04 (снова актуальна), D33 (часть про отсутствие соединения).
**Статус v3.1:** механика уточнена D53–D54. Кнопка называется
`ПОДКЛЮЧИТЬСЯ`; успех больше **не** открывает мини-игру отправки, а занимает
out-слот отдельным `TcpConnection`. До соединения файлы прикреплять нельзя.

## D46 — запросы на конкретные файлы, 1–4

**Решение:** запрос хранит **конкретные `file_id`** в `required`; число
файлов — **1–4** по `hours[].request_mix`. При создании выбираются реальные
файлы из пула: свободные, не прикреплённые и не затребованные другим
запросом. На карточке имена обязательных файлов видны сеткой 2×2.

  файл отклоняется с подсказкой.
- **Жёсткая резервация:** обязательный файл нельзя уничтожить, унести на стол
  или прикрепить к другому запросу (`required_by`).
- Пропавший файл (`failed`/`malicious`/удалён) показывается как **«ПОТЕРЯН»**;
  директор пытается подставить свободный файл того же типа, иначе отправка
  невозможна.
- Таймер — **30 + 7×timer_level**, максимум **65 с**; замирает в мини-игре,
  соединении, очереди out-слота и передаче.

- H1-затравка: seed-файл `text` + сразу запрос на него; первый пакет в `t=0`.
  Анти-голодание создаёт запрос, если активных нет и есть свободный файл
  (минимальный зазор 3 с).
**GDD:** §3, §7, §13, §17.
**Заменяет:** D32; обновляет D01, D06, D09.

## D52 — перестройка туториала

**Решение:** вместо ленты подсказок — **5 событийных шагов**:

  пройдено.
- Кнопка **«ОБУЧЕНИЕ»** в главном меню сбрасывает флаг и запускает повтор:
  в новом забеге — с подготовки, в идущем — с текущего часа.

## D53 — TCP-соединение как отдельная сущность

**Решение:** TCP-соединение хранится отдельно от запроса —
`scripts/entities/tcp_connection.gd` (`TcpConnection`): `id`, `client_name`,
`client_id`, `ip`, `request_id`, `slot_index`, `hour`, `connected_at`.
`HourDirector.active_connections` — словарь живых соединений; `Request`
держит только `connection_id` и флаги.

- **До соединения файлы прикреплять нельзя:** drag в карточку отклоняется,
  `attach_file` отвечает «СНАЧАЛА УСТАНОВИТЕ СОЕДИНЕНИЕ».
- Кнопка `ПОДКЛЮЧИТЬСЯ` — справа снизу на карточке, только TCP. Она запускает
  `ConnectionGame` (3 попадания). Успех создаёт `TcpConnection` и занимает
  **out-слот**; в слоте видны имя клиента и случайный IPv4, данных запроса
  там нет.
- После успеха мини-игра отправки **не открывается**: её запускает только
  `ОТПРАВИТЬ`, когда прикреплены все обязательные файлы.
- `ОТКЛОНИТЬ` отменяет запрос и закрывает его соединение; `reject`/`timeout`/
  конец часа освобождают слоты.
- Слоты общие для приёма и отправки: `1 + slot_level`, максимум 5.
  TCP-соединение может занять единственный слот и заблокировать приём — это
  осознанное требование.
**GDD:** §3, §7, §11, §11.1, §17.
**Уточняет:** D45; заменяет часть D33 про отсутствие соединения.

## D54 — Idle-слот после успешной отправки

**Решение:** успешная TCP-отправка удаляет запрос и расходует файлы, но
**не** закрывает соединение: `TcpConnection.request_id` очищается, слот
остаётся занятым (idle) до ручного `ОТКЛЮЧИТЬ` на слоте. Отключение
мгновенное, без проверок и мини-игр.

- Отключение во время подготовки/передачи прерывает передачу: выплаты нет,
  файлы не расходуются и возвращаются в папки, запрос остаётся активным;
  соединение нужно устанавливать заново.
- Повторное использование idle-соединения новым запросом не предусмотрено:
  каждый TCP-запрос проходит свою мини-игру соединения и занимает свой слот.
- `reject`/`timeout`/конец часа закрывают соединение и освобождают слот.
**GDD:** §3, §11, §17.
**Уточняет:** D45/D53.

## D55 — UDP-риск и лот «UDP-повторитель»

**Решение:** у UDP нет соединения; успех определяется роллом **в конце
передачи**. Шанс:

```
P = min(0.40 + 0.10 × udp_level, 0.80)
```

- Новый лот `lot_udp` «UDP-повторитель»: 4 уровня, цены **60 / 120 / 210 /
  350 $**, шанс **40 → 50 → 60 → 70 → 80 %**. Всего лотов — **9**, дерево —
  **8 825 $**.
- **Успех:** обычная выплата UDP (`×0.85`), файлы расходуются, запрос
  удаляется.
- **Провал:** выплаты и денежного штрафа нет, **−3 SLA**, файлы не
  расходуются, запрос остаётся, `udp_failures` +1, повтор через **4 с**,
  out-слот освобождается, streak сбрасывается. Повтор — снова мини-игра
  отправки и передача.
- Карточка показывает шанс (`UDP · ШАНС N %`) и после провала —
  `ПОТЕРЯ ПАКЕТА · ПОВТОР N с`.
**GDD:** §11, §11.2, §14.
**Заменяет:** часть D50 (8 лотов / 8 085 $) и числа D33 про UDP.

## D58 — файлы-каталог и темп прихода

**Решение:** файлы **не расходуются**. После успешной отправки
`registry.detach_file()` только снимает привязку к запросу; файл остаётся в
папке, занимает свои клетки и сразу доступен пулу следующих запросов
(`file_cooldown_after_send_sec = 0`). То же — при отмене, таймауте, отключении
и UDP-провале.

- Общего лимита числа файлов на забег нет. Приход задаёт **скорость**:
  `spawn_window = 0.75 × duration`; интервал — `spawn_window / hours[].files`
  с джиттером ±20 %, поэтому последний файл успевает до конца окна.
- `hours[].files` (**6, 6, 7, 8, 9, 9, 10, 10, 10**) — скорость/ожидаемое число
  файлов за окно часа, а не жёсткий cap забега и не остаток бюджета. Переноса
  между часами нет (carry = 0); служебного предела на число файлов нет.
- Папки докупаются в подготовке (180 $, до 6); к финалу в симуляторе обычно
  **5–6 папок**.
**GDD:** §6, §11, §11.2, §26.
**Заменяет:** D02/D33/D54/D55 в части «файлы расходуются при успешной
отправке».

## D59 — запросы без `request_cap`

**Решение:** отдельного `request_cap` нет. Темп запросов задаёт
`hours[].send_interval` (**20, 24, 18, 24, 24, 24, 24, 24, 24** с), а
ограничитель — только число **одновременно активных** запросов
`hours[].active_requests` (**2/2/2/3/3/3/4/4/4**). Новые запросы не спавнятся
в последние **10 с** часа (`REQUEST_SPAWN_CUTOFF_SEC`).

- Анти-голодание работает только для **первого** запроса часа
  (`requests_spawned == 0`); H1 bootstrap создаёт первый запрос сразу.
  Дальше директор не обгоняет `send_interval`.
- Запрос выбирает 1–4 файла из пула папок по `request_mix`; набор не связан
  с тем, какие файлы пришли в этом часе, — подходят и старые файлы из папок.
**GDD:** §7, §13.
**Заменяет:** числа `request_cap` из D05/D46 и формулировку «анти-голодание
не даёт панели простаивать» (теперь только первый запрос).

## D60 — окно спавна атак от длительности часа
