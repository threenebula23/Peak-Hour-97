# PEAK HOUR v3 - balance simulation report

Generated by `tests/sim_balance.py` from `data/balance.json`.
Seeds: **240**, hours: **9**, dt: **0.25 s**, send quality q=**0.85**, attack quality q=**0.85**, protocol: **TCP**.

## Model assumptions

- Spawn: file budget from `hours[].files` (+ carry), spawn only during 75% of the hour (225 s), interval 225/budget with +/-20% jitter; H1 spawns its first packet at t=0. A full buffer freezes spawns without burning the budget.
- Types: `hours[].type_weights` only; zero weight never spawns.
- Unsent files persist across hours (the folder is not cleared); only files consumed by a successful send disappear. Unspawned budget is carried separately, capped at 20 files/hour.
- Requests: `request_cap` and `active_requests` from `hours[]`; interval `hours[].send_interval`; count from `request_mix`; a request reserves available files at spawn and does not consume request budget when no files exist.
- Player: competent, attaches after 1.5 s + 1 s/file, plays a no-timer send minigame for 7 + 1.5*(tier+1) seconds (3 tiers). TCP adds 4.2 s connection time and 4% of attempts miss it (-4 SLA). The minigame pauses packet spawn/loading but not other request timers (production order).
- Timers: request `30 + 7*timer_level` (cap 65), packet 20 s. Timers pause in the player's own minigame and in the out-slot queue; payout uses `time_left` snapshotted at send start.
- Transfers: `base_time_sec * 0.90^speed_level * max(1, load/capacity)`; slots are shared by receive and send; files are consumed on successful send.
- Payout: exact `round(base_sum * speed * quality * multi * protocol * streak * money_mult)`; TCP x1.15, UDP x0.85; recv_fee is added on receive and is not multiplied.
- Folder: `grid.folder_dims[folder_level]`, 2 free folders at start; each extra folder costs `constants.folder_new_cost` (180 $) in prep, up to `constants.folders_max` (6). `lot_folder` buys more cells; fragmentation is not modelled, cell capacity/occupancy is.
- Shop: 3 weighted offers after each hour, `last_offer` x0.5, pity x1.5, no rerolls (locks are irrelevant), at least one affordable offer; buy the best affordable predicted-ROI lot while ROI >= 0.5 before H9, and any positive ROI in the final prep (there is no shop after H9).
- ROI proxy: `money` = next `shop[].value` step of projected remaining income; `slots`/`speed`/`channel`/`timer`/`folder`/`sla`/`shield` use measured bottlenecks from the previous hour. It is deterministic, not an oracle.
